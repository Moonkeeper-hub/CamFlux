# CamFlux development instructions
Read docs/MVP.md and docs/ARCHITECTURE.md before implementation. Use C#, .NET 10 LTS, WPF, MVVM, Windows x64. Keep core logic independent of WPF. Use one supervised FFmpeg process per enabled camera. Never invoke a shell with user-provided arguments; use ProcessStartInfo.ArgumentList. Never log credentials or full authenticated URLs. Store passwords with Windows DPAPI CurrentUser. No hardcoded real server addresses or secrets. Do not require administrator rights or modify system PATH. Use verified pinned FFmpeg builds with SRT support; validate hashes before installation and document provenance/license. Do not silently switch encoders or claim hardware support without a runtime probe. Keep UI responsive; cancel operations and terminate child processes on exit. Add unit tests for URL building, device parsing, validation and supervisor state transitions. Run build/tests on Windows CI; report untested hardware behavior explicitly. Work in a branch and submit PR, do not merge. Keep scope to requested milestone.
